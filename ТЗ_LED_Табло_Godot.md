# Как правильно ставить задачу ИИ-агенту (Godot + Android)

## Общие принципы

1. **Не давайте всё одним сообщением.** Агент (Claude Code и подобные) работает лучше, когда задача разбита на этапы: сначала архитектура → потом базовый функционал → потом визуал → потом пресеты → потом экспорт.
2. **Явно указывайте стек**: Godot (актуальная стабильная версия на момент старта — проверить отдельно, на момент написания последняя стабильная 4.6.x), GDScript (не C#, если не нужен), целевая платформа Android, минимальный API уровень.
3. **Просите план перед кодом.** Первое сообщение агенту — не "напиши код", а "предложи архитектуру сцен и синглтонов для такого-то функционала, без кода, только план". Это экономит кучу времени на переделки.
4. **Держите правила и ТЗ как два отдельных файла-контекста.** Правила работы агента — в `CLAUDE.md` (см. отдельный файл), техническое задание с фичами — в этом файле. Многие агентские инструменты (Claude Code, Antigravity) подхватывают такие файлы автоматически в каждой новой сессии — уточните в настройках инструмента, чтобы не вставлять вручную каждый раз.
5. **Тестируйте сборку после каждого крупного этапа**, а не в конце. Экспорт под Android с первого дня, даже с пустым проектом — чтобы убедиться, что пайплайн (Android SDK, JDK, keystore) настроен.
6. **Отдельно проговаривайте разрешения (permissions)** — микрофон нужен и для записи голоса ("рация"), и для аудио-реактивного пресета "Party" (см. раздел про пресеты) — оба используют одно и то же разрешение `RECORD_AUDIO`, запрашивать нужно один раз.
7. **Для Google Play** заранее закладывайте: политику конфиденциальности (обязательна, т.к. приложение использует микрофон и рекламу), target API level (актуальный на момент публикации), заполненную анкету по контенту, иконки/скриншоты нужных размеров.
8. **Используйте git с первого дня.** Коммит после каждого завершённого этапа — если следующий запрос агенту что-то сломает, у вас есть к чему откатиться.
9. **Фиксируйте критерий готовности перед началом этапа** — коротко: "этап считается завершённым, когда...". Без этого не всегда понятно, когда останавливаться и переходить к следующему шагу.

# Техническое задание: приложение «LED Display»

## Принципы дизайна UI/UX (простой и красивый интерфейс — Premium Mobile App)

Ориентир по ощущению — минимализм, много "воздуха", плавность, минимальная глубина навигации (стиль, знакомый по лучшим современным мобильным приложениям). Важно: копировать конкретный визуальный стиль конкретных производителей (шрифты, иконки, фирменные элементы) нельзя — это защищённая интеллектуальная собственность. Ниже — сами принципы + open-source альтернативы для их реализации в Godot.

### Общие принципы
- **Минимум цветов** в самом интерфейсе управления: один акцентный цвет + нейтральная палитра (белый/чёрный/оттенки серого). Яркость и разноцветность — на самом табло, не в меню настроек.
- **Много пустого пространства** между элементами — не перегружать экран.
- **Минимальная глубина навигации**: от главного экрана до любой настройки — максимум 1-2 касания.
- **Крупные зоны нажатия**: минимум 44x44 dp на кнопку/переключатель.
- **Плавные переходы**: анимация открытия панелей/переключения экранов через `Tween` с плавным easing (ease-out), 60 FPS.
- **Согласованность**: одинаковые скругления, отступы и стили кнопок по всему приложению — задаются один раз через Theme-ресурс.
- **Без ощущения "прототипа"**: единая дизайн-система с первого экрана, а не разнородные панели, слепленные по ходу разработки.

### Практическая реализация в Godot
- **Единый Theme-ресурс** (`.tres`): все стили кнопок/панелей/полей ввода через `StyleBoxFlat` с одинаковым `corner_radius` и мягкой тенью (`shadow_size`, `shadow_color` с низкой прозрачностью).
- **Шрифт (UI)**: свободные геометрические шрифты — например Inter, Manrope или Nunito Sans (открытые лицензии, хорошо читаются, "премиальный" вид).
- **Иконки**: единый набор простых линейных иконок (например, открытая библиотека Lucide Icons — бесплатна для коммерческого использования).
- **Панели настроек как bottom sheet**: выезжающая снизу панель поверх текущего экрана, а не отдельный полноэкранный переход.
- **Тёмная тема** как основная — согласуется с "тёмный экран с ярким текстом" сутью приложения.
- **Адаптация под любые экраны**: телефон и планшет, через anchors/containers, без фиксированных пиксельных координат.
- **Поддержка жестов**: double-tap (fullscreen), возможно swipe для переключения между панелями настроек.

## 1. Общая концепция

Мобильное приложение-имитация светодиодного табло (как уличные LED-вывески), с полноценным набором инструментов кастомизации (шрифты, цвета, фон, эффекты движения), готовыми тематическими и сигнальными пресетами, функцией "рации" (запись/воспроизведение голоса) и системой сохранения собственных проектов табло.

## 2. Главный экран

- **Мини-превью табло** в верхней/центральной части экрана — показывает текущий текст с текущими настройками в уменьшенном виде.
- **Двойной тап (double tap)** по превью → разворачивает табло на весь экран (fullscreen mode, скрыть статус-бар).
- **Двойной тап по fullscreen-режиму** → возврат к обычному экрану с элементами управления.
- Ниже превью — панель управления: поле ввода текста, кнопки настроек (текст/LED/фон/цвет/пресеты/проекты), кнопки Старт/Пауза/Стоп.
  *(Кнопка экспорта анимации временно убрана из MVP — см. раздел "Отложено" в конце файла.)*

## 3. Редактор текста и анимация

- Поле ввода текста (поддержка эмодзи через системную клавиатуру, кириллица).
- **Выбор шрифта** — из набора предустановленных шрифтов, поддерживающих кириллицу и эмодзи-фолбэк (см. техническую рекомендацию в разделе 4 про рендеринг — выбор шрифта не ломает LED-эффект, так как эффект накладывается поверх готового рендера текста).
- **Жирный / курсив** — как варианты начертания выбранного шрифта.
- **Интервал между буквами** (letter spacing) — регулируемый.
- Размер текста / масштаб LED-матрицы.
- **Режимы движения** (доступны для любого текста, не только в пресетах):
  - Статично (без движения)
  - Слева направо / справа налево (горизонтальный скролл)
  - Вверх / вниз (вертикальный скролл)
  - Мигание (появление/исчезание с заданной частотой)
  - Печатание (typewriter — текст появляется по одному символу)
  - Пульсация (плавное изменение яркости/масштаба текста)
  - Волна (волнообразное смещение букв)
  - Bounce (отскок — упругое появление/движение текста)
- Управление: **Старт / Пауза / Стоп** — явные кнопки, а не только "включено/выключено".
- Настройка скорости движения (слайдер — для скролла это скорость, для мигания/пульсации — частота).

## 4. Визуальные настройки LED

- Настройка вида "лампочек":
  - Форма точки: круг / квадрат / ромб
  - Размер точки и расстояние между точками (плотность матрицы)
  - Яркость (brightness)
  - Эффект свечения (glow/bloom)
  - Blur (мягкость краёв точки)
  - **Цвет включённых диодов** (то есть основной цвет текста)
  - **Цвет выключенных диодов** (то, что видно в промежутках между "горящими" точками — на настоящих LED-табло это тёмно-серый/почти чёрный, не чистый чёрный — важная деталь для реалистичности эффекта)
- Рекомендация по реализации: **не использовать самодельный bitmap-шрифт как основной способ рендера** (потребует вручную рисовать паттерн точек для каждой кириллической буквы, а цветные эмодзи в принципе не ложатся в монохромную bitmap-маску). Вместо этого — рендерить текст выбранным пользователем системным/векторным шрифтом (Godot поддерживает Unicode, кириллицу и цветные эмодзи через системные фолбэки) в `SubViewport`, получить результат как текстуру, и поверх неё шейдером сэмплировать по сетке точек: в каждой ячейке шейдер смотрит на яркость/цвет текста под ней и рисует там точку нужной формы, цвета и размера (а в пустых местах — точку цвета "выключенного диода"). Так LED-эффект — чисто визуальный пост-процесс поверх любого текста/шрифта/эмодзи, без ограничений по алфавиту.

## 5. Фон

- Цвет фона (сплошной).
- Градиент (два и более цвета, направление настраиваемое).
- Изображение как фон — импорт через системный **Photo Picker** (на современных Android версиях не требует runtime-разрешения на доступ к галерее, только системный выбор файла).
- Прозрачность фона (актуально в режиме превью, если фон приложения должен просвечивать).
- Режим "полностью чёрный" (актуально для OLED-экранов — экономит батарею и выглядит наиболее реалистично как настоящее табло).

## 6. Цвет текста и палитры

- Ввод цвета: RGB, HSV, HEX — все три способа доступны в одном color picker (переключение вкладками/полями).
- Готовые палитры (набор подобранных сочетаний цветов).
- Избранные цвета (пользователь сохраняет часто используемые).
- Недавние цвета (автоматически последние использованные, без ручного сохранения).

## 7. Управление проектами

"Проект" — это сохранённая комбинация всех настроек табло (текст, шрифт, анимация, LED-настройки, фон, цвет) как единый Resource (`.tres`), которую можно сохранить, переименовать, продублировать или удалить.

- **Сохранение проекта** — с названием (по умолчанию — начало введённого текста + дата).
- **Недавние проекты** — список последних открытых/изменённых, сортировка по дате.
- **Дублирование проекта** — создаёт копию с независимыми настройками.
- **Удаление проекта** — с подтверждением (не должно быть случайным одним тапом).
- **Автосохранение** текущего состояния (не именованного как отдельный проект) — чтобы при случайном закрытии приложения не терять текущую работу.
- Технически: `ProjectManager` (autoload) читает/пишет список проектов в `user://projects/`, каждый проект — отдельный `.tres`-файл с метаданными (имя, дата создания/изменения) + все параметры табло.

## 8. Пресеты

Пресеты делятся на два типа по поведению: **сигнальные** (мигание + звук, по двухфазному циклу сигнал↔текст) и **тематические** (декоративная анимация, без сирены).

### Сигнальные пресеты

| Пресет | Визуал | Звук |
|---|---|---|
| Police | Мигание красный (левая половина) / синий (правая половина), несколько готовых паттернов на выбор | Сирена полиции, регулировка громкости |
| Ambulance | Мигание бело-синее | Сирена скорой помощи |
| Fire Truck | Мигание красное | Сирена пожарной |
| Warning | Мигание жёлтое | Без звука или сигнал предупреждения (опционально) |
| SOS | Мигание белым по паттерну азбуки Морзе (три коротких / три длинных / три коротких) | Звук СОС по тому же паттерну |
| Taxi | Мигание жёлтое (иной паттерн, чем Warning — более частое/иное расположение) | Без звука по умолчанию |
| Security | Мигание оранжевое | Без звука по умолчанию, опционально короткий сигнал |

Для Police дополнительно: несколько готовых **шаблонов мигания** (не только левый-красный/правый-синий поочерёдно — вариативность паттернов), регулировка скорости и яркости отдельно от общих настроек LED, полноэкранный режим по умолчанию при активации, встроенная сирена с регулировкой громкости, и режим **"рация"** (см. ниже) — запись голоса и воспроизведение с эффектом рации, с повтором записи.

**Двухфазный цикл** (применим ко всем сигнальным пресетам): фаза "Сигнал" (мигание + звук, 1-2 сек по умолчанию) → фаза "Текст" (если введён — показывается в выбранном режиме анимации) → повтор. Если текст не введён, работает только фаза "Сигнал" по кругу. Длительность фазы "Текст" — либо настраиваемая вручную, либо рассчитывается по длине текста и скорости анимации (чтобы бегущая строка успевала проехать хотя бы раз).

### Тематические пресеты

| Пресет | Поведение |
|---|---|
| Party | Цветомузыка — анализ звука через микрофон (`AudioEffectSpectrumAnalyzer` на той же аудио-шине, что уже используется для "рации" — новое разрешение не требуется), цвет/яркость LED реагируют на громкость и частоты окружающего звука/музыки |
| Love | Анимация сердечек (пульсация/всплывание), розово-красная палитра |
| Happy Birthday | Праздничная анимация (аналог конфетти из точек), яркая мультицветная палитра |
| Christmas | Новогодняя тема — красно-зелёная палитра, анимация "снежинок" из точек |

Тематические пресеты тоже поддерживают показ пользовательского текста (как дополнительная фаза или как оверлей поверх анимации — решить на этапе реализации, что выглядит лучше для конкретного пресета).

Технически: каждый пресет — это `Resource` (`.tres`) с параметрами (цвета, паттерн мигания/анимации, путь к аудиофайлу, тип поведения — сигнальный/тематический) — не хардкод в коде, чтобы легко добавлять новые пресеты в будущем.

### Функция "рация" (запись и воспроизведение голоса)

- Кнопка записи (`AudioEffectRecord` на шине микрофона).
- Запрос разрешения `RECORD_AUDIO` на Android (добавляется в Android export preset + runtime permission request) — общее для рации и пресета Party.
- Кнопка воспроизведения записанного — с эффектом рации (лёгкий band-pass фильтр + шум через `AudioEffect`).
- **Повтор записи** — воспроизведение зацикленно, если нужно.
- Хранить последнюю запись в `user://`.

## 9. Архитектура в Godot (рекомендации агенту)

- **Autoload-синглтоны** (только там, где действительно нужно общее состояние на всё приложение):
  - `AppSettings` — текущие настройки табло (шрифт, цвета, скорость, режим анимации, форма LED, фон).
  - `PresetManager` — загрузка/применение пресетов (сигнальных и тематических) из ресурсов.
  - `AudioManager` — сирены/звуки, запись голоса, спектральный анализ для Party.
  - `ProjectManager` — сохранение/загрузка/дублирование/удаление проектов, автосохранение.
- **Сцены**:
  - `MainScreen.tscn` — превью + панель управления.
  - `LedBoard.tscn` — переиспользуемый компонент табло (превью и fullscreen используют один и тот же компонент), рендерит текст через SubViewport + dot-matrix шейдер.
  - `FullscreenBoard.tscn` — обёртка над `LedBoard` на весь экран с обработкой double-tap.
  - `TextEditorPanel.tscn`, `LedSettingsPanel.tscn`, `BackgroundPanel.tscn`, `ColorPickerPanel.tscn`, `PresetsPanel.tscn`, `ProjectsPanel.tscn`, `RecorderPanel.tscn`.
- Один компонент `LedBoard` переиспользуется везде — превью и fullscreen всегда синхронизированы, не два разных рендера.
- Связь между независимыми панелями настроек и `LedBoard` — через сигналы, а не прямые ссылки друг на друга.

## 10. Реклама и монетизация (баннер)

- **Решение по монетизации (MVP)**: только рекламный баннер, без покупок внутри приложения. Полноценный Google Play Billing — не входит в MVP, требует отдельного этапа и решения, что продавать. Отложено до появления реальных данных по установкам после запуска.
- **Задел на будущее**: в `AppSettings` — функция/флаг `is_premium()` (сейчас всегда `false`), от которой зависит показ баннера и доступность будущих премиум-фич.
- Внизу экрана — рекламный баннер, показывается **на всех экранах, кроме fullscreen-режима табло**.
- Реализация: Android-плагин (обёртка над AdMob или аналог), баннер — нативный Android View поверх Godot-окна.
- Логика показа: `hide_banner()` при входе в fullscreen, `show_banner()` при выходе, с учётом `is_premium()`.
- Тип баннера: `ADAPTIVE_BANNER` предпочтительно (аккуратнее выглядит).
- В форме Data Safety (Google Play) обязательно декларировать сбор рекламного ID через SDK.
- Если таргетированная реклама в ЕС/UK — нужна интеграция Google User Messaging Platform (UMP SDK) для согласия пользователя.

## 11. Android / Google Play

- `Android Export Preset`: package name, version code/name, min/target SDK (проверить актуальные требования Google Play на момент публикации).
- Разрешения: `RECORD_AUDIO` (рация + Party). Изображение для фона — через Photo Picker, без отдельного runtime-разрешения на современных версиях Android.
- Подпись APK/AAB (keystore), формат `.aab` обязателен для Play Console.
- Подготовить: иконку, скриншоты (телефон + планшет), политику конфиденциальности (микрофон + реклама), Data Safety форму.
- **Важно для категории/модерации**: приложение имитирует сирены и мигалки спецслужб. Рекомендуется: категория "Развлечения" (Entertainment), явное указание в описании и внутри приложения, что это имитация/развлекательная функция, а не настоящее устройство спецслужб.

## 12. Этапы работы с агентом (рекомендуемый порядок и критерии готовности)

1. Пустой Godot-проект + успешный экспорт на Android + базовый Theme-ресурс (шрифт, цвета, скругления) с самого начала.
   *Готово, когда: пустой .apk/.aab собирается и запускается на реальном устройстве без ошибок.*

   *Готово, когда: все варианты фона и способы выбора цвета работают и сохраняются в текущей сессии.*
5. Главный экран с превью + double-tap fullscreen + рекламный баннер (скрытие в fullscreen).
   *Готово, когда: double-tap стабильно переключает превью↔fullscreen, баннер корректно показывается/скрывается.*
6. Сигнальные пресеты (Police/Ambulance/Fire Truck/Warning/SOS/Taxi/Security) — двухфазный цикл сигнал+текст.
   *Готово, когда: все 7 пресетов запускаются, звук и мигание синхронны, текстовая фаза работает при наличии текста.*
7. Тематические пресеты (Party с аудио-анализом, Love, Happy Birthday, Christmas).

9. Управление проектами (сохранение/дубль/удаление/недавние/автосохранение).
   *Готово, когда: проект можно сохранить, найти в недавних, продублировать и удалить без потери других проектов.*

## Отложено (не входит в MVP, вернуться позже)

### Экспорт анимаций (гифки/видео)

- Возможность экспортировать текущую бегущую строку в анимированный файл (GIF или короткое видео/WebM) для отправки в мессенджеры.
- Реализация: рендер кадров табло через `Viewport` → `get_texture()` → сохранение серии PNG → сборка в GIF. Для сборки GIF в Godot нет встроенного метода — нужен либо самописный GIF-энкодер (LZW), либо экспорт через `MovieWriter` (ненадёжно на Android в релизе), либо нативный Android-плагин (MediaCodec) — самый надёжный, но самый трудозатратный вариант.
- Признано наиболее сложной частью проекта — переносится на этап после публикации MVP в Google Play.

## Дифференциаторы (после MVP, не клон рынка)

Анализ похожих приложений (LED Scroller / LED Banner) показал, что рынок насыщен "party/реклама"-приложениями с одинаковым набором фич. Экстренные пресеты + рация выделяют приложение — конкурентов с такой тематикой не найдено. Ниже — идеи для усиления этого отличия, по возрастанию сложности.

### 1. Вибрация синхронно с сигналом — *сложность: низкая*
- `Input.vibrate_handheld()`, без нативных плагинов, синхронизируется с таймером мигания.

### 2. Реальный строб через фонарик (torch) — *сложность: низкая-средняя*
- Android-плагин на `CameraManager.setTorchMode()`, готовые open-source Godot-плагины уже существуют.

### 3. Quick Settings Tile (плитка в шторке уведомлений) — *сложность: средняя*
- Нативный `TileService`, встраивается через custom Android build template. Мгновенный доступ к последнему пресету без открытия приложения.

### 4. Виджет на рабочий стол с превью — *сложность: средняя-высокая*
- `AppWidgetProvider` + `RemoteViews`. Ограничение: обновление не чаще ~раз в 30 минут без доп. механизмов.

### 5. Синхронизация между устройствами (мульти-телефон) — *сложность: высокая*
- Nearby Connections API / Bluetooth, разрешение на геолокацию для BLE. Начать с упрощённой версии ("отправить то же сообщение на телефон рядом").

**Рекомендуемый порядок:** 1 → 2 → 3 → 4 → 5, всё после публикации MVP.
